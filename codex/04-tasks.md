# 04. Codex 작업 — 피드백만 작성한다

## ★ 작업 범위 (가장 중요)

**Codex 는 이미 작성된 교재를 읽고 → 부족한 부분을 피드백으로 만들고 → 표로 정리한다.** 그게 전부다. 교재 본문(`k8scert/**/*.md`)을 직접 고치거나, 스크린샷을 캡처하거나, 내용을 생성하지 **않는다**. 실제 반영(편집·캡처)은 별도 주체(메인 Claude 에이전트/사람)가 수행한다.

**Codex 환경에는 클러스터가 없다**(교재 작성자 환경과 다름). `kubectl`·tart·SSH·캡처 불가. 따라서 교재의 명령·출력을 라이브로 검증하지 못하며, **"문서에 무엇이 있고 무엇이 빠졌는가 / 출력이 스크린샷 형식인가 텍스트인가"** 라는 형식·완성도 관점으로만 판정한다(05 문서 참조).

**산출물의 핵심은 "표"다.** 모든 피드백은 ⓐ파일별 요약 표 + ⓑ부족분 상세 표(또는 목록)로 정리한다. 사람이 표만 봐도 "어느 파일의 무엇을 고쳐야 하는지" 한눈에 들어와야 한다.

| Codex 가 하는 것 | Codex 가 하지 않는 것 |
|:--|:--|
| 교재를 읽고 02·03 기준으로 평가 | ❌ `k8scert/**/*.md` 본문 편집 |
| 부족분을 **피드백 문서**로 작성 | ❌ 스크린샷 캡처·이미지 생성 |
| 자동 무결성 점검 실행(읽기) | ❌ 클러스터 상태 변경(apply/delete) |
| 무엇을 어떻게 고칠지 `fix` 제안 | ❌ 교재 내용 신규 생성 |
| | ❌ 커밋·푸시(사용자/메인이 수행) |

즉 **산출물 = 피드백 파일들** 뿐이다.

## 산출물: 피드백 파일

### 1) 자격증별 피드백 (필수)

각 자격증마다 다음 경로에 작성한다(기존 파일이 있으면 갱신):

```
k8scert/<CERT>/FEEDBACK-codex.md      # CERT ∈ {KCNA, KCSA, CKA, CKAD, CKS}
```

> 기존 `FEEDBACK-최종재검토.md`(자동 검토 산출물)와 **구분**하기 위해 `FEEDBACK-codex.md` 로 따로 쓴다. 덮어쓰지 않는다.

**형식(자격증별 파일):**
```markdown
# <CERT> Codex 검토 피드백

> 생성: <날짜> · 기준: codex/02-authoring-standards.md, codex/03-review-checklist.md

## 요약
- 단독합격 추정 N/M · 평균 가독성 X.X · 스토리라인 X.X
- 스크린샷 활용: good A / partial B / none C
- 잔여 부족분 합계 K (HIGH h / MED m / LOW l)
- HIGH 카테고리 분포: 스크린샷부족 x, 실습재현불가 y, ...

## 파일별 표
| 파일 | 합격 | 가독성 | 스토리 | 스샷 | H/M/L |
|:--|:--:|:--:|:--:|:--:|:--:|
| daily/day01.md | O | 4 | 5 | good | 2/3/1 |
| ... | | | | | |

## 부족분 상세 (표로 정리 — 필수)
| 파일 | 심각도 | 카테고리 | 위치 | 문제 | 고칠 방법(fix) |
|:--|:--:|:--|:--|:--|:--|
| daily/day01.md | HIGH | 스크린샷부족 | 문제 2~5 풀이 | 출력이 인라인 주석(`# 출력:`)으로만 있음 | 각 풀이에 `검증 - 기대 출력:` + 실제 캡처(images/day01-11~14) 삽입 |
| daily/day01.md | MED | 스토리라인누락 | 2.2 Watch | 폴링 방식 한계 서술 없음 | "N초마다 전체 조회로 CPU 낭비" 1~2문장 보강 |
| ... | | | | | |
```

각 행은 반드시 **심각도(HIGH/MED/LOW) · 카테고리 · 위치(섹션/줄범위) · 문제(무엇이 왜 부족) · fix(어떻게 고칠지 구체 제안)** 5열을 채운다. `카테고리` 는 03 문서 표의 8종 중 하나. (행이 너무 많으면 HIGH 를 위에 모으고 LOW 는 접어도 된다.)

### 2) 전체 요약 (필수)

```
codex/FEEDBACK-SUMMARY.md
```

5종을 한눈에 비교하는 표(자격증별 합격 N/M, HIGH 수, 주요 카테고리)와 **우선순위 권고**(어느 자격증·어느 파일·어느 카테고리부터 반영하면 효과가 큰지)를 담는다. 반영은 Codex 가 하지 않으므로, **반영 담당자가 바로 착수할 수 있는 작업 목록** 형태로 정리한다.

### 3) 무결성 리포트 (필수)

```
codex/FEEDBACK-INTEGRITY.md
```

03 문서 §A 의 자동 점검 결과(펜스 균형·깨진 링크·```text 펜스·빈펜스 출력블록·인라인 주석 출력)를 그대로 싣는다. 위반이 있으면 파일·위치를 나열한다(고치지 말고 보고만).

## 검토 진행 방법

1. `codex/` 의 01~05 문서와 `k8scert/CLAUDE.md`, `k8scert/.review-loop-state.json` 을 읽는다.
2. 03 문서 §A 자동 무결성 점검을 실행한다(읽기 전용) → `FEEDBACK-INTEGRITY.md`.
3. 자격증 5종을 순회하며 각 파일을 02·03 기준으로 평가한다. 분량이 많으므로 자격증 단위로 나눠 진행해도 된다.
   - 우선순위: **실기 3종(CKA·CKAD·CKS) > 이론 2종(KCNA·KCSA)**. daily 파일이 분량·가치가 크다.
4. 자격증별 `FEEDBACK-codex.md` 를 작성한다.
5. 전부 끝나면 `FEEDBACK-SUMMARY.md` 로 종합한다.

## 평가 시 특히 확인할 것 (2회차 검토에서 빈번했던 부족분)

- ` ```bash ` 안 **인라인 주석 출력**(`# 출력:`, `# 기대:`, `# ca.crt namespace token`) → §1 위반, `스크린샷부족` 으로 기록.
- 시험 문제 풀이에 **검증 스크린샷 누락**.
- `ssh admin@<...-ip>` **자리표시자** → 이 저장소는 `ssh <vm-별칭>` 사용(`실습재현불가`).
- 매니페스트가 참조하는 **선행 리소스 생성 명령 누락**(`실습재현불가`).
- **스토리라인 4요소 중 "직전 기술과의 차이" 누락**(`스토리라인누락`).
- **약어 첫 등장 풀이 누락**(`용어비약`).
- 일별 양식의 **자가점검/직접해보기 절 누락**, **섹션·문제 번호 불일치**(`구조`).
- **사실 오류**(잘못된 포트·경로·필드·명령)(`정확성오류`).

## 금지

- 교재 본문 편집·이미지 추가·클러스터 변경·커밋/푸시. **피드백 파일 작성만 한다.**
- 출력을 추정해서 "이렇게 나올 것"이라고 단정하지 않는다(검토는 문서에 있는 것을 평가하는 것이지, 없는 출력을 지어내는 것이 아니다).
