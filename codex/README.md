# Codex 작업 지시 (k8scert 교재 검토 → 피드백 표 작성)

> # ⛔ 가장 먼저 — 절대 규칙 (어기면 작업 무효)
>
> 1. **Codex 는 교재 작성자(macOS)와 완전히 다른 환경에서 동작한다.** 이 환경에는 **클러스터·tart·kubeconfig·kubectl·SSH·GUI 가 없다.**
> 2. **절대 무엇도 "실행"하거나 "캡처"하지 않는다.** `kubectl`·`tart`·SSH·스크린샷 캡처·`kubectl apply/get/exec`·클러스터 접속 — **전부 금지**. 시도조차 하지 않는다(환경에 없어서 실패할 뿐 아니라, 역할 자체가 아니다).
> 3. **Codex 는 오직 "이미 작성된 문서 자체를 읽고 리뷰"하는 데만 집중한다.** 산출물은 **피드백(표)** 뿐이다. 교재 본문을 고치지도, 새 내용을 생성하지도, 이미지를 만들지도 않는다.
>
> 한 줄로: **"문서를 연다 → 읽는다 → 부족한 점을 표로 적는다." 그 외의 모든 행위(실행·캡처·편집·생성)는 하지 않는다.**

이 폴더는 **Codex(또는 다른 코딩 에이전트)에게 이 저장소의 K8s 자격증 교재(`k8scert/`)를 읽고, 부족한 부분을 찾아 피드백으로 정리하도록 지시**하기 위한 브리핑 문서 모음이다. Codex 는 작업 시작 전에 이 폴더의 문서를 **번호 순서대로 전부 읽는다.**

## Codex 의 역할 (딱 이것만)

> **이미 작성되어 있는 교재들을 읽고 → 부족한 부분을 피드백으로 만들고 → 표로 정리한다.**

- Codex 는 **교재 본문을 수정하지 않는다.** 스크린샷을 캡처하지도, 내용을 새로 생성하지도 않는다. 산출물은 **피드백 문서(표 포함)** 뿐이다.
- **Codex 환경에는 클러스터가 없다**(교재 작성자의 환경과 다름). `kubectl`·tart·SSH·캡처 불가. 그래서 Codex 는 "교재에 무엇이 있고 무엇이 빠졌는가"를 **문서만 보고** 판정한다. (상세: [05-environment-commands.md](05-environment-commands.md))
- 실제 반영(편집·캡처)은 별도 주체(메인 에이전트/사람)가 한다.

## 한 줄 정체성

> 이 저장소의 실제 tart 멀티클러스터(macOS Apple Silicon)를 실습장 삼아 K8s 자격증 5종(KCNA·KCSA·CKA·CKAD·CKS)을 로컬에서 준비하는 **교육 과정 교재**를 만든다. 강의자료는 클라우드가 아니라 **로컬에 실제로 떠 있는 클러스터에서 직접 실행·검증**한 결과로 채운다.

## 가장 중요한 원칙 (먼저 읽어라)

1. **출력은 무조건 실제 터미널 스크린샷 PNG.** 명령 실행 결과를 ` ```text ` 나 빈 ` ``` ` 코드블록, 인라인 주석(`# 출력:`)으로 적는 것은 **금지**다. 출력을 지어내지 않는다. (상세: 02 문서 §1)
2. **검증되지 않은 내용을 단정하지 않는다.** 클러스터에서 실제로 실행할 수 없으면 "(미캡처)"로 명시한다.
3. **기존 작업 기준 문서는 [`../k8scert/CLAUDE.md`](../k8scert/CLAUDE.md) 가 단일 기준(SSOT)** 이다. 이 codex 문서와 CLAUDE.md 가 충돌하면 CLAUDE.md 를 따른다.
4. **커밋·푸시는 사용자 승인 시에만.** 기본은 "작성 → 검토 → 승인 시 푸시".

## 현재 진행 상태 (이어받기)

진행 상태는 [`../k8scert/.review-loop-state.json`](../k8scert/.review-loop-state.json) 에 기록돼 있다. 작업 시작 시 이 파일을 먼저 읽는다.

- **검토→반영 루프**를 최소 3회 반복하는 중이다(사용자 지시).
- 1회차: 검토 + 텍스트 보강(774 edits) + **모든 §4① 출력블록을 실측 스크린샷으로 전환 완료**.
- 2회차: 재검토 87/93 완료(단독합격 CKA 20/25·CKAD 14/19·CKS 15/19·KCNA 11/14·KCSA 8/10). 텍스트 보강 진행 중.
- 잔여 HIGH 부족분은 자격증별 `k8scert/<CERT>/FEEDBACK-최종재검토.md` 에 정리돼 있다.

Codex 는 이 루프를 이어받아 **재검토 → 부족분 반영 → 무결성 검증**을 수행한다.
