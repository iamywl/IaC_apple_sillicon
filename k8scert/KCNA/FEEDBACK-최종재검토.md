IPVS 모드가 '커널 수준 로드밸런싱을 직접 수행'한다는 의미와 '트래픽을 프록시하지 않는다'의 차이가 분명하지 않아 학생이 혼동할 수 있다. → iptables 모드 설명과 IPVS 모드 설명을 두 개의 개별 항목(7번, 7-a번)으로 분리하거나, 하나의 항목 안에서 '모드별' 구분 레이블을 붙여 각각의 동작을 독립적으로 기술한다.
- **MED** `맥락점프` _섹션 8(트러블슈팅 시나리오, 464~502행) - 실습 전제 blockquote와 실제 명령 형식_ — 실습 전제 blockquote가 있으나 트러블슈팅 검증 명령이 '실측 검증: kubectl describe pod ...' 형태의 텍스트 지시로만 제시된다. 학생이 직접 따라할 수 있는 완전한 명령(클러스터 명시, 네임스페이스, 실제 리소스명 예시)이 없어 재현 가능성이 낮다. → 각 시나리오에 최소한 재현용 명령 예시를 bash 코드블록으로 제공한다. 예: 시나리오 1에 'kubectl --kubeconfig ~/sideproejct/IaC_apple_sillicon/kubeconfig/dev.yaml run test-pending --image=nginx --requests=cpu=100 --limits=cpu=100m'처럼 실제로 Pending 을 발생시킬 수 있는 명령을 붙인다.
